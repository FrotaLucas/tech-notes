## 1. Reducing LLM Usage

When building an AI application, try to avoid using an LLM whenever a simpler and more cost-effective solution can handle the request.

Use an LLM only when other approaches are insufficient.

Possible alternatives include:
- Rule-based logic
- Classifiers
- Routers
- Traditional application code

**Goal:** Reduce operational costs and make expenses more predictable by replacing unnecessary LLM calls with simpler, more deterministic components.

> Note: Replacing variable LLM inference costs with fixed costs depends on the alternative architecture. Infrastructure, hosting, and maintenance may still generate costs.

## 2. Output Tokens and Confidence

LLM outputs may include token-level probability information, depending on the model and API.

- **Output tokens:** Tokens generated by the model in its response.
- **Token probabilities:** Some models expose log probabilities that indicate how likely particular tokens were under the model's probability distribution.

Important distinction: token probabilities do not directly tell you whether an entire answer is correct. A fluent answer can still contain incorrect information.

## 3. Guardrails

Guardrails help control how users interact with an AI application and what the application is allowed to do.

Common purposes:
- Prevent unauthorized disclosure of sensitive information.
- Reduce abuse and misuse of the application.
- Restrict requests that fall outside the application's intended purpose.
- Enforce input and output policies.

Guardrails can include validation rules, access controls, content filters, and model-based checks.

## 4. Classifiers

A classifier categorizes a user's request so the application can decide how to process it.

Examples:
- Technical question
- Customer support request
- Request involving sensitive data
- Out-of-scope question

Classification can help the application select an appropriate workflow before calling an LLM.

## 5. Routers

A router directs a request to the most appropriate processing component or model.

For example:
- Simple questions → cheaper or smaller models.
- Complex questions → more capable models.
- Predictable requests → deterministic application logic.
- Restricted requests → validation or refusal workflow.

**Goal:** Balance response quality, latency, and cost by selecting the appropriate processing path for each request.

## 6. Embeddings

Embeddings transform text into numerical vectors in a multidimensional space.

These vectors can be compared to estimate semantic similarity between phrases or documents.

Typical use cases:
- Semantic search
- Retrieval-Augmented Generation (RAG)
- Finding related documents
- Matching user questions with relevant knowledge

Text with similar meanings may have vectors that are close together under an appropriate similarity measure.

## 7. Conversation History with LangChain

LangChain provides components that can help manage conversation history and integrate it into an AI application.

Conversation history can help the application maintain context and generate responses that are more relevant to the user.

### Managing token usage

Long conversations can increase context size and inference costs.

A rough estimate sometimes used for English text is:

`Estimated tokens ≈ number of characters / 4`

This is only a heuristic. Actual token counts vary by language, text content, and tokenizer.

A practical workflow:
1. Estimate or count the tokens in the conversation.
2. Check the model's context-window limit.
3. Estimate the cost of the input and expected output.
4. Keep only the relevant conversation history when appropriate.
5. Summarize older messages when the conversation becomes too long.

**Important:** Summarizing a conversation can reduce token usage, but the summary should preserve important user preferences, decisions, and context.

## 8. Modular Prompt Files

Store prompts in separate files instead of embedding all instructions directly in application code.

This makes prompts easier to maintain, test, and customize for different tasks or business areas.

### Example structure

```text
prompts/
├── technical-assistant.txt
└── customer-support.txt
```

### Example prompts

**`technical-assistant.txt`**

Contains instructions that specialize the AI assistant in a particular technical domain or business area.

**`customer-support.txt`**

Contains instructions that specialize the AI assistant in customer service, including tone, response guidelines, and escalation rules.

The application can load the appropriate prompt based on the user's request, selected workflow, or business context.

## Key Takeaways

- Avoid unnecessary LLM calls by using simpler alternatives where possible.
- Use classifiers and routers to select the appropriate processing path.
- Implement guardrails to protect data and control application behavior.
- Use embeddings for semantic similarity and retrieval.
- Manage conversation history to control context size and costs.
- Store prompts in modular files to improve maintainability.
